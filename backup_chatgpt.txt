============================================================
WATERMEDIA ARCHITECTURE — DO NOT REGRESS
============================================================
Do NOT return to the old homegrown JavaCV/FFmpeg player without an extraordinary reason.
Historical custom-player failures included:
- 720p stalls
- A/V desync
- timestamp/rebasing problems
- prebuffer/deadlock problems
- seek corruption
- costly frame catch-up logic

Historical 1.1.x detail only:
- Photography 1.1.1 used WATERMeDIA 2.1.26.
- On that old version, calling `player.preRender()` on the render thread was necessary to upload video frames; omitting it caused audio with a black screen.

CURRENT 1.2.x detail:
- Photography now targets WATERMeDIA 2.1.37.
- WATERMeDIA 2.1.35+ automatically uploads VLC frames through its render executor.
- `preRender()` is deprecated for the current architecture and MUST NOT be reintroduced merely because the 1.1.x backup once required it.
- `VideoPlayerSession.textureId()` reads `player.texture()`; WATERMeDIA updates the texture itself.

Known historical user tests:
- ~1 hour ~650x385 MP4: described by user as playing extremely well.
- ~50 sec ~1280x738 H.264 MP4: normal playback works with WATERMeDIA.

H.264 SEEK SHIELD — CURRENT 2.1.37 STRATEGY
The 1280x738 H.264 file can briefly expose damaged/macroblocked reference frames after seek.
Old 2.1.26 solution froze the previous texture by withholding preRender.
That is impossible with current automatic upload.
Current solution:
- keep a seek recovery timer
- cover the video area with black + `A procurar...` during the shield
- ~1.2s minimum / ~2.5s hard maximum for large video
- shorter guard for lower resolution
Do not remove without retesting the 1280x738 regression case.

CUTSCENE END DETECTION
Never rely exclusively on `isEnded()`.
The current cutscene tracks actual playback and uses multiple signals:
- isEnded()
- reaching near duration then leaving PLAYING
- STOPPED after real playback with a short grace period
This exists because an old `skip false` cutscene once became an infinite prison at EOF.
Preserve the safety behavior.

ONLINE FAILURE SAFETY
- online startup timeout: ~30 seconds
- playback error becomes visible briefly then cutscene safely closes/cancels callbacks
- missing YouTube extension gives a friendly error
- never create another `skip false` prison due a dead/broken online URL

1.2.0 ALPHA 2 — IMPLEMENTATION DETAILS
============================================================
Canonical grammar:
/video play <source> [targets] skip <true|false>
    [volume <0-100>]
    [speed <0.25-4.0>]
    [subtitles "<file.json>"]
    [fadein <0-60>]
    [fadeout <0-60>]
    [onskip "<minecraft command>"]
    [then <minecraft command>]

Existing commands without Alpha 2 options remain supported.
`volume` and `speed` are accepted individually and in either order BEFORE subtitles/fades/callbacks.
`then` remains final/greedy.

VOLUME
Examples:
/video play "intro.mp4" @a skip true volume 20
/video play "intro.mp4" @a skip true volume 100
- range 0..100
- default 80% to preserve previous Photography VideoPlayerSession behavior
- sent in PlayVideoPayload as volumePercent
- client sets session volume before playback start

SPEED
Examples:
/video play "intro.mp4" @a skip true speed 0.5
/video play "intro.mp4" @a skip true speed 2
/video play "intro.mp4" @a skip true volume 30 speed 1.5
- range 0.25..4.0
- default 1.0x
- serialized as permille (250..4000) in PlayVideoPayload
- VideoPlayerSession applies WATERMeDIA/VLC `setSpeed(float)` after playback has actually opened
- speed failure logs a warning but should not kill video playback
- speed intentionally ignored on LIVE streams

ONSKIP
Example:
/video play "intro.mp4" @a skip true onskip "say SALTOU" then say TERMINOU
Rules:
- literal is lowercase `onskip`
- requires `skip true`; server rejects it with skip false
- onskip command uses a normal Brigadier string, so COMMANDS WITH SPACES MUST BE QUOTED
- this is specifically so a later greedy `then` can coexist
- an allowed ESC skip sends success=true, skipped=true from client
- natural EOF sends success=true, skipped=false
- errors/replacement/forced removal send success=false, skipped=false
- `/video stop` is cancellation, NOT onskip
- onskip executes ONCE PER `/video play` INVOCATION, immediately on the FIRST allowed target skip
- with multiple targets, it does NOT run once per player
- `then` still runs once after all targets naturally finish or allowed-skip

LIFECYCLE NETWORK PAYLOAD CHANGES
PlayVideoPayload now carries:
- source
- allowSkip
- fadeInMillis
- fadeOutMillis
- subtitleSource
- callbackId
- volumePercent
- speedPermille

CutsceneFinishedPayload now carries:
- callbackId
- success
- skipped

Every cutscene gets a callback/session UUID now, even if no `then`, because gamerules need server-side active-cutscene tracking.

ACTIVE PLAYER TRACKING
`CutsceneCallbackManager` tracks player UUID -> active callback id + starting world + starting XYZ.
The active record is cleared only when the matching cutscene ends/cancels. This prevents an old screen's delayed completion packet from clearing a newer replacement cutscene.

ALPHA 2 GAMERULES
============================================================
Both default FALSE for backwards compatibility:
/gamerule photographyFreezeDuringCutscenes true
/gamerule photographyInvulnerableDuringCutscenes true

Implementation class:
src/main/java/com/saymp/photography/PhotographyGameRules.java

FREEZE
- server tick hook: ServerTickEvents.END_SERVER_TICK
- only active Photography cutscene players are affected
- player anchor is captured when `/video play` starts
- velocity reset to zero
- if moved from anchor beyond tiny tolerance, server requestTeleport restores XYZ
- yaw/pitch are current values, so camera rotation remains free
- if player changes dimension, current implementation does NOT yank them back across dimensions; freeze becomes best-effort there

INVULNERABLE
- ServerLivingEntityEvents.ALLOW_DAMAGE
- if entity is an active cutscene ServerPlayerEntity and gamerule is true, normal damage is cancelled
- after cutscene lifecycle ends, normal damage behavior returns
- do not overpromise administrative effects such as `/kill`; test normal attacks/environment damage

=== 1.2.0 ALPHA 2 COMPILE FIX ===
- First Alpha 2 build failed at compileJava in PlayVideoPayload.java.
- Cause: Minecraft/Fabric 1.21.1 PacketCodec.tuple(...) supports a maximum of 6 fields, while Alpha 2 PlayVideoPayload has 8 fields after adding volumePercent and speedPermille.
- Fix: replaced the 8-field PacketCodec.tuple with PacketCodec.of(PlayVideoPayload::write, PlayVideoPayload::new) and explicit encode/decode of all 8 fields.
- No gameplay behavior or command syntax was intentionally changed by this fix.

ALPHA 4 JSON SCHEMA
Global settings may now include:
- typewriter: true|false (default false)
- typewriterSpeed: 1..240 characters per second (default 30)
- speakerColor: optional default color for speaker labels
- speakers: object mapping speaker names to reusable style configs

Each settings.speakers entry may override:
- color (dialogue color)
- nameColor (speaker label color)
- size
- position
- shadow
- bold
- italic
- background
- backgroundColor
- typewriter
- typewriterSpeed

Each subtitle cue may now include:
- speaker: display name shown above dialogue
- name: accepted alias for speaker
- speakerColor: per-cue speaker-label color override
- typewriter
- typewriterSpeed
- all previous style fields

Style precedence:
1) global settings
2) matching speaker config (case-insensitive match)
3) individual cue override

TYPEWRITER RENDERING
- Text reveal is based on playback position minus cue.from.
- typewriterSpeed means Unicode code points/characters per second.
- Unicode code-point slicing avoids splitting surrogate pairs.
- Layout/background uses the FULL final subtitle dimensions while revealing text.
- Each typewriter line is anchored to its final centered position so it reveals left-to-right without horizontal jumping.
- Speaker label appears immediately and is not typewritten.

SPEAKER RENDERING
- Speaker label is bold and shown above the dialogue.
- Label has a separate color from dialogue.
- Speaker config color controls dialogue; nameColor controls label.
- Speaker-specific settings reduce repeated style fields in large subtitle files.
